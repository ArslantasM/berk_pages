Debugging

BERK,modern debugging toolsIt offers strong debugging support. Professional development experience with DWARF/PDB debug symbols, GDB/LLDB integration and VS Code debugging.

Debug Build

Activating Debug Symbols

# Debug modda derle (optimizasyon yok, debug sembolleri var)
berk-lang build --debug

# Veya
berk-lang build -g

Debug vs Release

FeatureDebug (-g)Release (-O2)
Debug symbols✅ Yes❌ None
optimization❌ None (-O0)✅ Yes (-O2)
Compilation speed🚀 Fast🐌 Slow
Working speed🐌 Slow🚀 Fast (10-50x)
Binary size📦 Large📦 Small
Stack trace✅ Detailed⚠️ Limited

GDB Debugger

Basic Usage

# Program GDB ile başlat
gdb ./output

# GDB in
(gdb) run                    # Programı çalıştır
(gdb) break main.berk:10     # 10. satıra breakpoint
(gdb) continue               # Devam et
(gdb) next                   # Sonraki satır (step over)
(gdb) step                   # Fonksiyon içine gir (step into)
(gdb) print x                # Değişken değeri
(gdb) backtrace              # Call stack
(gdb) quit                   # Çık

Breakpoint Types

# Satır breakpoint
(gdb) break main.berk:25

# Fonksiyon breakpoint
(gdb) break hesapla

# Koşullu breakpoint
(gdb) break main.berk:30 if x > 10

# Watchpoint (let değiştiğinde break)
(gdb) watch x

# Tüm breakpointleri listele
(gdb) info breakpoints

# Breakpoint sil
(gdb) delete 1

Variable Review

# Basit let
(gdb) print x
$1 = 42

# Struct
(gdb) print kisi
$2 = {isim = \"Ali\", yaş = 25}

# Array
(gdb) print sayılar[0]@5  # İlk 5 eleman

# Pointer
(gdb) print *ptr

# Format belirle
(gdb) print/x x           # Hex
(gdb) print/t x           # Binary
(gdb) print/f x           # Float

LLDB Debugger

Basic Commands

# LLDB başlat
lldb ./output

# LLDB in
(lldb) run
(lldb) breakpoint set --file main.berk --line 10
(lldb) breakpoint set --name hesapla
(lldb) continue
(lldb) next
(lldb) step
(lldb) frame variable x
(lldb) bt                    # Backtrace
(lldb) quit

VS Code Debugging

launch.json Configuration

.vscode/launch.json:

{
  \"version\": \"0.2.0\",
  \"configurations\": [
    {
      \"name\": \"Debug BERK Program\",
      \"type\": \"cppdbg\",
      \"request\": \"launch\",
      \"program\": \"${workspaceFolder}/output.exe\",
      \"args\": [],
      \"stopAtEntry\": false,
      \"cwd\": \"${workspaceFolder}\",
      \"environment\": [],
      \"externalConsole\": false,
      \"MIMode\": \"gdb\",
      \"miDebuggerPath\": \"gdb.exe\",
      \"setupCommands\": [
        {
          \"description\": \"Enable pretty-printing\",
          \"text\": \"-enable-pretty-printing\",
          \"ignoreFailures\": true
        }
      ],
      \"preLaunchTask\": \"build-debug\"
    }
  ]
}

tasks.json (Debug Build)

.vscode/tasks.json:

{
  \"version\": \"2.0.0\",
  \"tasks\": [
    {
      \"label\": \"build-debug\",
      \"type\": \"shell\",
      \"command\": \"berk-lang\",
      \"args\": [\"build\", \"--debug\", \"-o\", \"output.exe\"],
      \"group\": {
        \"kind\": \"build\",
        \"isDefault\": true
      },
      \"problemMatcher\": []
    }
  ]
}

VS Code Debugging Features

1. Breakpoints

  • ✅ Line breakpoints (F9)
  • ✅ Conditional breakpoints (right click)
  • ✅ Logpoints (print output, does not stop)
  • ✅ Function breakpoints

2. Stepping

shortcutAction
F5Continue
F10Step Over (go over the function)
F11Step Into (go inside the function)
Shift+F11Step Out (exit function)

In the "Variables" panel on the left:

  • Local variables

4. Watch Expressions

5. Call Stack

Shows function call history - click on any frame

6. Debug Console

x + 10
kisi.isim

Conditional Breakpoint Examples

// Sadece x > 100 olduğunda break
function işle(x: sayı) do
    if x < 0 do  // Breakpoint burada: x < 0
        return 0
    end
    return x * 2
end

Debugging Best Practices

  1. ✅ Use debug build:

    berk-lang build --debug

  2. ✅ Prefer logpoints(program does not stop)

  3. ✅ Conditional breakpointsuse (in loops)

  4. ✅ Watch expressionsadd (complex expressions)

  5. ⚠️ Optimization offmust be in debug mode

  6. ⚠️ stack overflowcontrol:

    ulimit -s unlimited  # Linux

Debugging Techniques

1. Binary Search Debugging

Put a breakpoint in half of the code - which half is the error?

2. Rubber Duck Debugging

Explain the code line by line (to yourself or to someone)

3.Print Debugging

print(\"x değeri: {}\", x)
print(\"Buraya geldi mi?\")

4.Use of Assertion

iddia_et(x > 0, \"x pozitif olmalı\")

Troubleshooting

No Debug Symbols

# Kontrol et
file output.exe | grep \"not stripped\"

# Strip edilmişse yeniden derle
berk-lang build --debug

Breakpoint Doesn't Stop

  1. Make sure it is compiled in debug mode
  2. Optimization must be off (-O0)
  3. Is the line number correct?

Variable Values ​​Not Shown

Optimization may have removed the variable - use debug build
